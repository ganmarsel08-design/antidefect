## 3. Порядок

1. **Пакет автору.** `blind1-author-package.md` (версия 1.2) передаётся в новую изолированную беседу ChatGPT. Только он.
   - Пакет не указывает, какие поля распознаёт программа: все 184 исходных поля словаря даны одним списком по алфавиту, без признаков части и критичности.
   - Автору не передаются: репозиторий, извлекатель, регулярные выражения, 9 историй разработки, прежние результаты и история разработки.
2. **Проверка врачом.** Врач проверяет клиническую правдоподобность (раздел 10). Замечания исправляет автор.
3. **Формальная проверка до заморозки** — `validate.py`, только форма:
   - схема и идентификаторы, ссылки;
   - типы и допустимые значения;
   - дословное наличие цитат в указанном месте. DOCX читается независимо от программы (zipfile + ElementTree);
   - **совпадение эталона чтения DOCX с XML документа**;
   - наличие в эталоне чтения всех дополнительных элементов, которые есть в XML;
   - минимумы набора.

   **Эталон чтения DOCX сверяется с XML полностью:** последовательность блоков основного текста (абзацы и таблицы — в общем порядке), текст каждого абзаца, строки и ячейки таблиц по порядку; для каждого типа дополнительного элемента — число и точный текст каждого элемента (надписи без дубликатов VML из `mc:Fallback`; колонтитулы — по частям; сноски, концевые сноски и примечания — по одному, без служебных разделителей); для рисунков и внедрённых объектов — число; удалённый текст.

   При ошибках архив возвращается автору. Исполнитель эталон не правит. Невыполненные минимумы — предупреждение; соответствующие риски отмечаются в отчёте как непроверенные или недостаточно представленные.
4. **Заморозка** — `freeze.js` → `freeze/blind1-freeze.json` (только если `validate.py` без ошибок; повторная запись запрещена):
   - SHA-256 архива и **полный перечень** входных файлов с SHA-256;
   - SHA-256 единого манифеста комплекта;
   - результат формальной проверки;
   - время.

   Манифест отправляется пользователю **до** прогона.
5. **Прогон** — `run.js` с `--freeze`. Выполняется один раз: каталог результатов не перезаписывается. Сырые результаты сразу получают права только на чтение и хэши в `RUN-MANIFEST.json`.
6. **Оценка** — `score.js` с `--freeze`. Тоже один раз: первичные результаты не перезаписываются, файлы — только для чтения, хэши — в `results-v1/MANIFEST.json`.
7. **Отчёт.**
   - Ошибки эталона после прогона — отдельный файл `gold-amendments.json`. Первичные метрики не пересчитываются; метрики с поправками — отдельной колонкой.
   - Ошибки оценщика — по разделу 2.
8. Хранение до утверждения отчёта — вне рабочего репозитория. После утверждения — `engine/test/fixtures/blind1/` по отдельному разрешению.

## 4. Подача документов и оценка чтения DOCX

**TXT:** UTF-8, удаление BOM, `\r\n` и `\r` → `\n` (как поле ввода страницы).

**DOCX (сквозной путь):** `readDocx(bytes, {JSZip})` → текст и предупреждения → `extract(text, {tz:'+05:00', documentId, warnings})`, как в `expert-app.js`.

**Чтение DOCX оценивается отдельно от извлечения.**

- **Эталон чтения** — `docx-text/<ID>.json` автора. До заморозки он сверяется с XML независимым чтением.
- **Полнота текста** = НОП слов (наибольшая общая подпоследовательность) / слова эталона. **Точность текста** = НОП / слова прочитанного текста.
  - Разделители ячеек `|` и пробелы не учитываются. Корректно прочитанная таблица ошибкой не является.
- **Выявление неполного чтения:** для каждого типа дополнительного элемента в документе должно быть предупреждение этого типа. Соответствие типов:
  - надпись → «надпись»;
  - рисунок → «рисунок»;
  - внедрённый объект → «внедрённый объект»;
  - верхний колонтитул → «колонтитул (header…)»;
  - нижний колонтитул → «колонтитул (footer…)»;
  - сноска → «сноски»;
  - концевая сноска → «концевые сноски»;
  - примечание → «примечания рецензента».

  Мера — выявлено / ожидалось по парам (документ × тип).
- **Ложное предупреждение** — сообщён тип, которого в документе нет. Предупреждение «рисунок» при наличии надписи ложным не считается: надпись хранится внутри рисунка.
- **Утечка** — текст дополнительного элемента (не короче 8 символов) или удалённый текст (не короче 4 символов) оказался в прочитанном тексте.
- **Извлечение по эталону чтения:** для DOCX `extract()` дополнительно запускается на тексте эталона чтения (абзац — строка; строка таблицы — ячейки через « | », как в программе). Это отделяет ошибки извлечения от ошибок чтения. Основные пороги считаются по сквозному пути.

## 5. Сопоставление кандидатов с эталоном

**Состав единиц учёта:**
- в полноту входят факты эталона **части A** (по замороженному `field-sets.json`, а не по разметке автора) со статусом не `superseded` и в месте `body` или `table`;
- факты части A в дополнительных элементах считаются отдельно («не видны программе»).

**Единица учёта:**

| Поле | Единица |
|---|---|
| обычное поле | уникальное значение поля в истории (повторы и `same_as` — одна единица) |
| `blood_gases`, `crp_samples` | элемент списка; ключ `drawn_at` |
| `xrays` | элемент; ключ `at` |
| `vent_changes` | элемент; ключ `at` + `parameter` |
| `gi_passage_restored` | наблюдение (значение + время или дата) |
| `abx_regimen` | одна запись схемы: набор препаратов без учёта порядка и регистра |

**Нормализация:**
- числа — запятая → точка, без допуска;
- перечни — точное равенство;
- текст — обрезка, пробелы, без учёта регистра, ё = е;
- дата-время — точное совпадение до минуты и смещения.

**Значения кандидата:**
- однозначное значение;
- альтернативы (выбирает врач);
- элементы списка;
- наблюдения динамики.

Элементы списка и наблюдения считаются однозначными.

**Классы единицы:**

| Класс | Условие |
|---|---|
| **В** | однозначное значение кандидата равно эталону |
| **ВА** | эталонное значение есть только среди альтернатив |
| **О** | значения нет, но у поля есть неверное значение кандидата (не совпадает ни с одним значением эталона, включая `superseded`). Ошибка **молчаливая**, если неверное значение однозначное. Подклассы: доза, число, время, да/нет, перечень, текст; для списков — свойства элемента или время элемента (элемент с теми же прочими свойствами, но другим временем); для динамики — время или значение |
| **П** | иначе |

**Ложные извлечения (ЛП):**
- Значения кандидата, не сопоставленные с единицами.
  - Совпадение с `superseded` — ЛП «устаревшее значение».
  - Иначе тип определяется по ловушкам с той же областью: `negation`, `plan` и т. д.; без ловушки — «не объяснено».
- Однозначные ЛП входят в знаменатель точности, ЛП в альтернативах приводятся отдельно.

**Источник:** для В и ВА проверяется, пересекается ли фрагмент кандидата с цитатой факта. Если нет — признак «верное значение из другого места». Ошибкой не считается, но приводится.

**Дата без времени:** факт `value: null` с `event_date`. Однозначный кандидат с датой-временем из того же места — молчаливая ошибка времени (время придумано).

**Ловушки:**
- срабатывание — значение кандидата поля ловушки, фрагмент которого пересекается с цитатой, равное `must_not_value` (или любое при `"any"`);
- `deleted_tracked_text` срабатывает, если удалённый текст оказался в прочитанном тексте;
- ловушка в дополнительном элементе или с цитатой, не найденной в поданном тексте, — «не проверяема».

## 6. Метрики

**Определения:**
- **Общая полнота** = (В + ВА) / все единицы. Строгая полнота = В / все единицы.
- **Полнота критических полей** — то же для критических полей части A:
  - масса, срок гестации, возраст;
  - все дозы, интервалы и единицы доз, время назначения и введения;
  - диагнозы и подозрения РДС, НЭК и сепсиса, стадия НЭК;
  - число факторов риска и признаков сепсиса, число признаков «красного флага»;
  - давление CPAP, FiO2, целевая SpO2;
  - время показания к АБТ, забора посева, начала и конца курса;
  - пассаж.
- **Точность значений** = В / (В + О + ЛП однозначные). Справочно: точность среди найденных = В / (В + О).

**Нулевые критерии** (k / N, где N — число возможностей ошибиться).

**Учёт ошибок (1.2).** Ошибка — конкретное значение кандидата. Если одно значение одновременно классифицировано как О, ЛП и срабатывание ловушки, оно считается **один раз**. В k входят также **опасные однозначные ЛП**, не связанные с текущим фактом эталона:
- по дозам — однозначные ЛП в полях доз, включая значение из устаревшей (`superseded`) записи;
- по времени — однозначные ЛП в полях даты-времени, лишние элементы списков и наблюдения динамики.

Такие ЛП, не совпавшие ни с одной возможностью из эталона, добавляются и в N.

| Критерий | N | k |
|---|---|---|
| Молчаливые ошибки доз и единиц | единицы полей доз + проверяемые ловушки `unit_not_field_unit` и `dose_without_unit` + опасные ЛП доз вне этих возможностей | уникальные значения: молчаливые О в полях доз, однозначные срабатывания этих ловушек, однозначные ЛП доз |
| Молчаливые ошибки времени | единицы полей даты-времени, элементы списков, наблюдения динамики, факты «дата без времени», проверяемые ловушки `time_without_date`, `date_without_time`, `relative_time`, `midnight_crossing` + опасные ЛП времени вне этих возможностей | уникальные значения: молчаливые О по времени, придуманное время, однозначные срабатывания, однозначные ЛП времени |
| Отрицания и планы, принятые за выполненное | единицы да/нет со значением «нет», **включая наблюдения динамики пассажа `gi_passage_restored` со значением «нет»** + проверяемые ловушки `negation`, `plan`, `conditional` | уникальные значения: «да» вместо «нет» и **любые** срабатывания этих ловушек, включая альтернативы |
| Ложные предварительные соответствия | раздел 7 | раздел 7 |

**Чтение DOCX:** выявление неполного чтения (порог 100%), ложные предупреждения, утечки, полнота и точность текста по каждому документу.

**Разбивки:**
- протокол;
- формат (DOCX сквозной, DOCX по эталону чтения, TXT);
- основание времени;
- типы ловушек;
- поля — в таблице ошибок.

**Контроль заимствования:** единица «заимствована», если её цитата содержит 3 подряд идущих слова (≥ 3 букв) из описания поля в словаре. Полнота приводится отдельно для заимствованных и остальных.

**Интервалы:**
- основной — кластерный бутстреп по историям: 10 000 повторов, seed 20261121, 2,5–97,5 перцентили. Факты одной истории не считаются независимыми;
- справочно — интервал Уилсона.

**Нулевые критерии:**
- при k = 0 — верхняя 95% граница 1 − 0,05^(1/N);
- при N = 0 — **«не проверен»**, выполненным не считается;
- если риск представлен в наборе мало, это прямо указывается в отчёте.

## 7. Влияние на 30 правил

- **Эталонные данные:** факты частей A и B со статусом не `superseded`, из любых мест документа (истина документа).
  - Поле с одним значением — это значение.
  - Несколько значений — значение с `primary: true`. Без него поле «неоднозначно в эталоне», правила с ним во входных данных — «зависит от выбора врача», в нулевой критерий не входят.
  - Списки — все элементы.
  - Динамика — самое раннее наблюдение.
- **Стресс-режим:** первое предложенное значение (первая альтернатива, первое наблюдение). **Это стресс-тест, а не модель работы врача.**
- **Осторожный режим:** только однозначные значения; поля с альтернативами и с динамикой из нескольких наблюдений остаются без данных.
- **Ярлыки** — как в `expert-view.js`, по каждому правилу и каждой его части, протокол — протокол истории.
- **Классы расхождения:**
  - **ложное предварительное соответствие** — на извлечённых данных «соответствие», на эталонных — иное;
  - ложное предварительное отличие;
  - переход в «недостаточно данных» или «неоднозначность»;
  - иное.

  Для каждого расхождения указываются поля-причины: входные поля правила с учётом производных, в которых данные отличаются.
- **Причина расхождения (1.3)** определяется для каждого поля-причины; у одного поля может быть несколько причин:
  - **ошибка чтения DOCX** — сведения в основном тексте, но цитата эталона отсутствует в прочитанном программой тексте, или извлечение по эталону чтения даёт верное значение, а сквозное — нет; а также сведения в дополнительном элементе, о котором программа **не** предупредила;
  - **сведения в дополнительном элементе, о неполном чтении которого программа предупредила** — факт эталона в надписи, сноске, колонтитуле и т. п., и предупреждение этого типа есть;
  - **ошибка извлекателя при корректно прочитанном тексте** — значение, видимое в основном тексте (эталон по фактам из `body`/`table`), извлечено неверно или не извлечено, и это не объясняется чтением; для TXT — всегда эта причина, если не другие;
  - **ограничение схемы полей или движка** — поле не входит в схему извлечения (часть B), либо параметр меняется во времени, а движок принимает одно значение (`gi_passage_restored` с несколькими наблюдениями).
- В отчёте приводятся: число расхождений по причинам и **отдельно — общее число ложных предварительных соответствий независимо от причины** и их разбивка по причинам. **Нулевой критерий считается по общему числу; причина его не смягчает.**
- **Нулевой критерий:**
  - N — пары (история × правило или часть) с эталонным ярлыком не «соответствие», без зависящих от выбора;
  - считается в обоих режимах, основной — стресс.

## 8. Что сохраняется (`results-v1/`, только чтение)

- `extraction/<ID>.json` — поданный текст, предупреждения и сырой вывод программы; для DOCX — также извлечение по эталону чтения;
- `run-info.json`, `RUN-MANIFEST.json` (хэши сырых результатов на момент прогона);
- `matching.json`, `reading.json`, `rules-impact.json`, `metrics.json`, `report.md`;
