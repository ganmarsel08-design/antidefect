# Дополнение к отчёту №1: замечание про `undefined` (ответ на аудит, issue №10)

Первоначальные результаты (`results-v1/`) не изменялись.

**Причина.** Проверяется 485 пар «правило/часть правила» на режим. В 36 парах (по 72 строки на оба режима) у программы нет метки части правила: когда применимость правила не установлена, движок возвращает метку только для правила целиком, без частей (например `RDS-007/start`). Оценщик сравнивал ключи по эталону и для отсутствующей метки писал `undefined` и класс «иное».

**Что это не затрагивает.**
- Ложные предварительные соответствия: 0 и не меняется. Метка отсутствует, а не «соответствие»; ключей, которые есть только в извлечении, нет (проверено отдельным скриптом, только чтение).
- Остальные пороги, метрики извлечения и чтения DOCX.

**Что искажено.** Строки с отсутствующей меткой попали в класс «иное» и в таблицы причин как отдельные расхождения, дублируя родительское правило. Без них: «иное» 94 вместо 130 (стресс и осторожный одинаково), «совпадает» 356 и «переход в недостаточно данных» 13 не меняются.

**Предложение.** В оценщике 1.5 (отдельный PR, после проверки ChatGPT) выделить класс «часть не оценивалась» и не включать его в «иное» и в подсчёт причин. Версия 1.4 и результаты первого прогона остаются как есть.
