# База медицинских правил (пилот, этапы 5–6, третий круг)

`pilot-rules.json` — 30 правил-кандидатов: РДС (№4/2016), НЭК (№185/2023), бактериальный сепсис (№185/2023), по 10 на протокол.
Схема `rules-0.2` (этап 6): 22 правила исправлены по итогам двух кругов экспертизы, 8 подтверждённых (RDS-001–006, RDS-008, RDS-009) побайтово такие же, как в коммите 2239c52.
Схема `rules-0.3` (третий круг, решения врача 20.11.2026): изменены записи 12 правил; из 8 ранее подтверждённых побайтово неизменны RDS-001, 002, 004, 005, 006, а RDS-003, RDS-008, RDS-009 изменены только по решению врача (`revision_round3`). Блокирующих неоднозначностей 28, противоречий 7 (CF-006, CF-007 — предлагаемые). Все 30 правил — кандидаты, `expert_confirmation: null`.
Отчёты: `docs/stage5-rules-pilot-report.md` (этап 5), `docs/stage6-rules-revision-report.md` (этап 6), `docs/round3-implementation-report.md` (третий круг).

**JSON не правится вручную.** Источник базы — `build/build_rules.py` (определения этапа 5) + `build/revisions_stage6.py` (слой правок этапа 6) + `build/revisions_round3.py` (слой правок третьего круга).
Тест `test_build.py` проверяет, что повторная сборка даёт побайтово тот же файл.

```
python3 rules/build/build_rules.py              # пересобрать rules/pilot-rules.json
python3 rules/build/build_expert_decisions.py   # пересобрать rules/expert-decisions.json
```

`expert-decisions.json` — решения экспертизы отдельно от базы (круги 1–2, уточнения C1–C7, 4 клинических комментария врача дословно, Q01–Q24 — все открыты, решения по исправлениям этапа 6 в `stage6_corrections`, контрольные суммы 8 подтверждённых правил на 2239c52, решения третьего круга в `round3` и в `decisions[].round3`). Статус правил он не меняет.

## Поля правила
| Поле | Смысл |
|---|---|
| `rule_id` | `RDS-001`, `NEC-001`, `SEP-001` … |
| `doc_id`, `protocol` | связь с записью реестра этапа 4 и конкретной редакцией (`protocols.<id>.edition`, SHA-256 локального PDF) |
| `source.section`, `source.quotes[]` | раздел и точные цитаты `{page, text, sha256}`; хэш — от нормализованного текста |
| `applicability` | описание и машинное условие (`all`/`any`, операции `eq gt gte lt lte in is_true is_false present`) |
| `requirement` | требуемое действие/ограничение и машинная проверка |
| `normativity`, `normativity_marker` | `обязательно` / `рекомендуется` / `может_применяться` / `не_рекомендуется` / `противопоказано`, по слову цитаты |
| `exceptions_and_caveats` | оговорки протокола |
| `required_data` | поля синтетического случая (словарь — `data_dictionary`) |
| `evidence_level` | только если указан в документе, со страницей |
| `ambiguities[]` | вопросы врачу (`decision: null`) |
| `kind` | требование / ограничение / сравнительное_положение |
| `ambiguities[].blocking`, `scope`, `blocks_when` | блокирует ли неоднозначность оценку (always / when / no) и в какой ситуации |
| `protocol_conflicts` | id объявленных противоречий; сами противоречия — в `protocol_conflicts` верхнего уровня, с цитатами и `active_when` |
| `status`, `expert_confirmation` | `кандидат, ожидает экспертного подтверждения`, `null` |
| `requirement.parts[]` (0.2) | части проверки `{part_id, description, applicability?, check}`; итог правила — самый осторожный исход применимых частей: неоднозначность → отличается → нет данных → совпадает |
| `ambiguities[].part` / `.parts`, `.blocks_when_by_part` (0.2) | к какой части относится неоднозначность и её условие для каждой части; без `part` — уровень правила (как в 0.1) |
| `ambiguities[].added`, `.machine_note` (0.2) | новая неоднозначность этапа 6; пояснение к машинному прочтению (текст и условия старых неоднозначностей не меняются) |
| `card_labels[]` (0.2) | подписи карточки эксперта `{id, label, when?, first?, quotes?}` — только отображение, исход не меняют; в `label` можно подставить значение поля `{поле}` (число — до 4 знаков, с запятой; нет значения — подпись не показывается) |
| `display_fields` (0.2) | поля, которые показываются в карточке, но не проверяются |
| `revision` (0.2) | решение второго круга и основание правки (раздел ТЗ, уточнение C) |
| `data_dictionary[поле]` (0.2) | `type`: `tri` / `enum` / `number` / `text` / `datetime` / `date` / `list` / `object` / `derived`; `values`; `false_means`; `derived_from`; `derived_from_optional` (вход, без которого значение всё равно может быть получено); `record_format`; `superseded_in_revised_rules_by` |

## Принципы
- Неоднозначность, которая блокирует оценку, переводит правило в состояние «Неоднозначность — ожидает экспертного решения»: ни «совпадает», ни «отличается» до решения эксперта.
- Противоречия протокола объявлены в базе с цитатами; они не выводятся из разных результатов правил.
- Неподтверждённые правила не дают окончательного вывода о качестве лечения. `engine/rules-engine.js` возвращает `final_conclusion: null` и статус «Требуется оценка эксперта»/«Недостаточно данных».
- Отклонение может быть обосновано врачом (`justifications[rule_id] = {text, author}`); обоснование передаётся эксперту и не меняет наблюдение автоматически.
- Дозы и показания — только из цитат. Пилот принимает только синтетические случаи (`synthetic: true`).

## Хронология и данные (этап 6)
- Отметки времени — только полные: `2026-01-05T10:00+05:00` (дата, время, часовой пояс). Только дата, без часового пояса, неверный формат → интервал не вычисляется («Недостаточно данных», причина в карточке).
- Невозможный порядок отметок (доза раньше назначения, конец курса раньше начала, результат раньше забора) → «противоречивая хронология», интервал не вычисляется.
- Интервалы и вычисляемые поля считает `engine/derive.js`; значения этих полей, введённые вручную, игнорируются.
- `unknown` / `неизвестно` / `no_record` и пустой список — нет данных, а не «нет».
- Календарные сутки (курс АБТ, дни НЭК, день начала ПП, «масса того же дня») — по часовому поясу организации `facility_utc_offset` (`+05:00`, `-03:00`, `Z`). Без него — по общему смещению отметок; отметки в разных смещениях или неверный формат пояса → «Недостаточно данных». Часы от пояса не зависят.
- Длительность курса АБТ — календарные сутки от первой до последней дозы завершённого курса (Q14 открыт; это временный режим ТЗ). Смена препарата курс не перезапускает; перерывы показываются.
- RDS-007, часть «отмена»: засчитывается только отмена ПОСЛЕ исключения ТБИ (затем RDS-007-A2); до исключения — «отличается»; одинаковое время — «Недостаточно данных».
- Дозы SEP-005/006: раздельно (1) согласованность записей — вычисленная доза, округлённая до точности записанной («25», «25,0», «25,00» различаются), только показывается; (2) вычисленная доза мг ÷ масса; (3) значение для оценки — вычисленная, если взвешивание (`weight_measured_at`) в тот же календарный день и не позже назначения (`*_prescribed_at`), иначе записанная в мг/кг с подписью, иначе нет данных. Клинического допуска нет (Q24 открыт).
- Признаки улучшения стр. 12 — информационный блок карточки; часть «улучшение» NEC-004 проверяет запись врача `clinical_lab_improvement_documented`.
- Источник факта: `sources[поле] = {document, fragment, author, recorded_at, confidence}`; обоснование: `justifications[rule_id] = {text, author, recorded_at, category, source, reference, drug_unavailable}`; категории — `clinical_indication`, `drug_unavailable`, `local_practice`, `physician_or_consilium_decision`, `other`. Ни источник, ни категория исход не меняют.
