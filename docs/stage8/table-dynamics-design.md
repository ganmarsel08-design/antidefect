## Разбор таблиц — контракт после ревью ChatGPT к 2177b19

Реализовано в `extract.js` и `case-builder.js`. Пороги, правила и словарь не менялись.

| Блокер | Как сделано |
|---|---|
| 1. pCO2 | В `blood_gases` (`paco2_mmhg`) попадает только при двух условиях: **явная** единица «мм рт. ст.» в заголовке и **явный** артериальный источник — подпись таблицы («артериальн…») или ячейка «Проба/Кровь». Венозная, капиллярная, неуказанный источник, без единицы, кПа — не извлекаются. **Физиологические диапазоны 6,5–7,8 и 10–150 удалены**: они не утверждены и могли скрыть критические значения. Значение передаётся как записано, только после поэлементного подтверждения. |
| 2. Смысл колонки времени | «Время забора» / «время исследования» / «выполнено» → `event_time`. Общая «Дата/время», «Дата» → `unknown`, нужно поэлементное подтверждение. «Время результата» не подменяет время забора: газы из такой таблицы не извлекаются. |
| 3. ИВЛ | Разница соседних строк **не передаётся** в `vent_changes`: это изменение между наблюдениями, а не действие в момент второй строки. Только `extraction.table_observations` (вне словаря, в случай не входят): наблюдения по строкам и изменения с интервалом `between`, обеими цитатами и пометкой «время действия врача неизвестно». Через пропуск, копию, неполную строку, обратное время и смену режима строки не сравниваются. Смену пациента по таблице определить нельзя, поэтому изменения в случай не попадают вовсе. Тест extract→case→derive→RDS-010: `vent_changes` в данных нет, ложного «совпадает» нет. |
| 4. Рентген | Модальность берётся только из ячейки «Исследование». УЗИ, КТ, МРТ — не рентген, даже если слово «рентген» есть в заключении. Строки «планируется», «назначено», «не выполнено» — не факт исследования. Отрицания учитываются: «не вертикально» → положение не определено, «не экстренно» → показание не определено. |
| 5. Списки | Каждый табличный элемент (`from_table`) подтверждается отдельно, **даже при `event_time`**. Групповое подтверждение и подтверждение списка целиком не проходят. Отдельный элемент можно **отклонить** с причиной (`{index, at, reject: true, reason}`): в `data` он не попадает, а в источнике остаются `excluded_elements` с цитатой и причиной. В журнале — решение по каждому элементу. Отклонить все элементы через этот механизм нельзя: для этого есть отклонение сведения целиком. |
| 6. Прочее | Повторяющаяся колонка одного смысла → таблица не разбирается, в предупреждениях: «таблица … не разобрана» (извлечение неполное). Десятичная точка принимается наравне с запятой. Таблица из DOCX (ячейки через « \| ») разбирается так же, тест есть. FiO2 по времени — наблюдение вне словаря, как записано (доля или %), без пересчёта. `fio2` стабилизации не заполняется и не меняется. UI: у каждого элемента «подтвердить» или «отклонить» с основанием или причиной; блок «Наблюдения ИВЛ / FiO2 из таблиц» с интервалами изменений. |

## Не сделано (нужно решение)
- **Отдельное поле «FiO2 / настройки ИВЛ по времени» в словаре** — изменение словаря, решение владельца и рецензента. Пока это только наблюдение вне случая.
- **Реакция врача на гипокапнию (RDS-010)** по таблице определить нельзя: таблица наблюдений не доказывает момент действия. Источником остаются текстовые записи действия («PIP снижен с … до … в 14:05»).
- **КОС и ИВЛ в тексте дневника** (не таблицей) — по-прежнему формулировки этапа 7.
