## 4. Эталон — уточнения по итогам набора №1
1. Ловушка `must_not_value: "any"` допустима, только если в эталоне **нет действующего факта** этого поля из той же цитаты. Если верное значение существует, ловушка перечисляет только запрещённые неверные значения (например, дату 00:00 или чужую дату). Валидатор 1.5 проверяет это и не принимает набор при противоречии.
2. Латиница в кириллическом слове («CРБ», «СРАP») — одно правило для всего набора: слово читается как кириллическое и сведения извлекаются; ловушка фиксирует только неверные значения.
3. **Определения полей — дословно по утверждённому словарю, без переопределения.** Автор размечает поле строго по тексту описания в таблице полей, например: `gentamicin_given` — «Назначен гентамицин»; `benzylpenicillin_given` — «Назначен бензилпенициллин»; `metronidazole_given` — «Метронидазол включён в терапию»; `immunoglobulin_given` — «Введён иммуноглобулин»; `first_abx_dose_administered_at` — «Время фактического введения первой дозы антибиотика». Поле «назначен» **не является** доказательством введения: факт и время введения размечаются только в полях, описание которых говорит о введении. Изменение словаря или эталона — только отдельным решением владельца и рецензента, не в этом задании.
4. **Время документа ≠ время события — единственный вариант разметки.** Время записи (дата-время заголовка записи, время подписи, время документа) **никогда не размечается действующим фактом поля времени события — ни с какой меткой** (`time_kind` допустим только `event_time`; `document_time` — ошибка набора, валидатор 1.5 её не принимает). Если в тексте есть только время записи, а поле — время события, факт этого поля **не создаётся**; вместо него автор вносит ловушку `document_time_as_event` (`field` — поле даты-времени, `must_not_value: "any"`, `quote` — дословная цитата заголовка записи, `correct_reading` — «время записи, не время события»). Время события — только когда текст прямо относит время к действию (`time_kind: event_time`). Оценщик 1.5: ловушка срабатывает, если программа выдала это время как время события; если выдала как время записи или неизвестного типа — ловушка выдержана. (Валидатор и оценщик покрыты тестами в PR №17: `v15-functional.test.js`.)
5. Каждое сведение, записанное в тексте, размечается, если поле есть в таблице полей; если автор сознательно не размечает — указывает причину в `author-notes.md`.

## 6. Самодостаточность итогового задания (требование рецензента к PR №14)

Он **не** содержит: ссылок на набор №1, его статистику, результаты, отчёты и внутренние ревью; формулировок вида «как в №1», «в №1 было …», «добавления к заданию №1»; названий файлов и PR проекта; примеров из набора №1. Все числа, определения полей (дословно по словарю), схема эталона, классы ловушек, требования к объёму/разнообразию/DOCX-элементам, форматы файлов и порядок передачи приводятся в нём явно. Текущий файл — черновик различий **для рецензента** (с отсылками к №1 для сверки), автору не передаётся и итоговым заданием не является.
