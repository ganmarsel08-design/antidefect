# ТЗ: модуль «Отклонение от протокола + обоснование» (Антидефект, черновик 0.1)

Статус документа: черновик для независимой экспертной проверки. Код модуля ещё не написан.

## 1. Принцип

Единственный критерий аудита: помощь оказана по действующему протоколу РК. Отклонение от протокола не является дефектом само по себе, но каждое существенное отклонение должно иметь проверяемое обоснование. Отсутствие рекомендации в протоколе не означает запрет назначения. Наличие публикации не означает, что назначение обосновано.

Программа не выносит окончательного решения. Окончательное решение принимает врач-эксперт или комиссия. Программа показывает, чего в обосновании хватает и чего нет.

## 2. Что считается отклонением

Проверка выполняется отдельно по каждому назначению или решению (препарат, доза, кратность, длительность, метод, исследование).

| Тип | Условие | Пример |
|---|---|---|
| A. Расхождение с протоколом | Протокол регулирует вопрос, назначение отличается | Доза или срок отличаются от указанных |
| B. Нет прямой рекомендации | Протокол вопрос не регулирует (поиск по всем применимым протоколам не дал совпадения) | Лечебный курс противогрибковой терапии |
| C. Показание не подтверждено | Назначение совпадает с протоколом, но условия применения у пациента не подтверждены данными | Профилактика флуконазолом при массе >1000 г |

Тип B нужно отличать от «протокол не найден программой». Если поиск не дал результата, статус «нет прямой рекомендации» ставится только после перечня просмотренных протоколов и разделов. Этот перечень сохраняется в результате.

## 3. Пять составляющих проверки

Для каждого отклонения программа заполняет пять блоков. Каждый блок содержит найденные факты с привязкой к месту в истории (дата, время, фрагмент) либо пометку «не найдено».

1. **Назначение.** Что назначено; что говорит протокол (протокол, №, раздел, цитата) либо «прямая рекомендация не найдена» и список просмотренных разделов; в чём отличие.
2. **Показания.** Диагноз, лабораторные и микробиологические данные, факторы риска, динамика, предшествующая терапия. Программа ничего не домысливает: только то, что есть в истории.
3. **Научное обоснование.** Источник, предъявленный врачом (ссылка, DOI/PMID, PDF). Поля: дизайн исследования, популяция, препарат и доза, результат, ограничения, год. Программа сверяет с пациентом, но не оценивает «качество» без данных: если сведений нет, пишется «не определено». Источники программа не выдумывает; непроверяемый источник помечается «не проверен».
4. **Документация.** Есть ли в истории запись врача с обоснованием, решение консилиума, оценка пользы и рисков, мониторинг эффективности и безопасности, информированное согласие, если требуется.
5. **Экспертный вывод.** Статус из раздела 4. Выводит программа как предложение, решение принимает эксперт.

## 4. Статусы

| Статус | Условие |
|---|---|
| Соответствует протоколу | Отклонения нет |
| Обоснованное отклонение | Заполнены показания, источник, запись в истории |
| Отклонение документировано не полностью | Заполнены не все три составляющие; в результате перечислено, чего именно нет |
| Требуется оценка эксперта | Данные есть, но оценка зависит от клинического суждения (применимость исследования, противоречивые данные) |
| Недостаточно данных | Невозможно определить, было ли отклонение |
| Потенциальный дефект | Установлено конкретное несоответствие обязательному требованию (например, противопоказание, прямой запрет в протоколе) |

Правила:
- «Потенциальный дефект» не ставится только из-за отсутствия записи в предоставленной истории.
- Любой статус можно изменить вручную с указанием причины и источника. Исходный результат программы не удаляется (журнал версий).
- Статус «Обоснованное отклонение» не означает, что назначение доказанно правильное и что комиссия его примет.

## 5. Условия, при которых отклонение не может быть «обоснованным» автоматически

- Есть прямое противопоказание в протоколе или инструкции препарата.
- Доза или путь введения превышают указанные в протоколе или инструкции без отдельной записи.
- Источник относится к другой популяции (не новорождённые) и нет обоснования переноса.
- Нет ни одной записи врача о причине назначения.

В этих случаях статус не выше «Требуется оценка эксперта».

## 6. Данные модуля

```
Deviation {
  id, patient_ref (псевдоним),
  order: {text, date_time, source_fragment},
  protocol_check: {protocols_searched[], match: found|not_found, quote, section},
  type: A|B|C,
  indications: [{fact, source_fragment, date_time}],
  evidence: [{citation, doi_or_pmid, verified, design, population, dose, outcome, limitations, year}],
  documentation: {physician_note, consilium, risk_benefit, monitoring, consent},
  missing: [string],
  status, status_set_by: auto|expert, reason, history[]
}
```

## 7. Требования к работе с данными

- Работа только с обезличенными или синтетическими историями до проверки требований РК к хранению данных.
- Исходная история не изменяется. Модуль только читает.
- Любой фрагмент, отправляемый внешнему ИИ, предварительно обезличивается; без отметки согласия не отправляется.
- ИИ используется только для извлечения фактов и сопоставления; статус определяется детерминированными правилами из раздела 4. Любая ссылка на источник проверяется человеком.

## 8. Пример (из практики)

Назначен лечебный курс противогрибковой терапии. Поиск по протоколам: в протоколах №185 (сепсис), №4 (РДС) и др. есть профилактика (флуконазол, нистатин), прямой рекомендации по лечебному курсу в просмотренных разделах нет. Протокол №231 (пороки развития диафрагмы) упоминает противогрибковую терапию «на основании бактериологических высевов», но схемы не даёт и применим только к этой группе. Для ребёнка без этого диагноза — тип B. Программа не ставит дефект; запрашивает: показание (посев, факторы риска, клиника), источник (статья), запись врача. Если все три есть, предлагает «Обоснованное отклонение», при отсутствии пишет, чего не хватает. Окончательное решение — за комиссией.

Это пример логики, а не подтверждение правильности конкретного назначения.

## 9. Критерии приёмки (для проверки PR)

1. Каждый тип отклонения (A, B, C) обрабатывается отдельным тестом.
2. Тип B не ставится без перечня просмотренных протоколов.
3. «Недостаточно данных» не превращается в дефект.
4. Выдуманные ссылки невозможны: все источники либо введены врачом, либо помечены «не проверен».
5. Ручное изменение статуса сохраняет исходный результат.
6. Не менее 10 синтетических случаев: по 2 на каждый статус, включая случай с противогрибковой терапией.
7. Исходный текст истории не меняется.

## 10. Открытые вопросы к врачу и эксперту

1. Нужны ли отдельные статусы для типов A, B, C или достаточно одного набора?
2. Какие отклонения считать несущественными (например, отличие кратности в пределах допустимого)?
3. Нужен ли консилиум обязательным условием для типа B?
4. Каков список протоколов РК, применимых в ОРИТН (часть датирована 2014–2017, актуальность не проверена)?
5. Кто в центре подтверждает статус «проверено» для правил реестра?
