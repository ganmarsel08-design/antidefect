# ТЗ: модуль «Отклонение от протокола + обоснование» (Антидефект, черновик 0.2)

Статус документа: черновик после первой экспертной проверки (PR №3). Код модуля ещё не написан.

Изменения относительно 0.1: тип отклонения и подтверждение показаний разделены на независимые параметры; научное обоснование разбито на четыре проверки; добавлены сигналы безопасности; учтена полнота предоставленной истории и реестра протоколов; задан приоритет статусов; число тестов исправлено (минимум 15).

## 1. Принцип

Единственный критерий аудита: помощь оказана по действующему протоколу РК. Отклонение от протокола не является дефектом само по себе, но каждое существенное отклонение должно иметь проверяемое обоснование. Отсутствие рекомендации в протоколе не означает запрет назначения. Наличие публикации не означает, что назначение обосновано.

Программа не выносит окончательного решения и не объявляет врача допустившим дефект. Она показывает, чего в обосновании хватает и чего нет. Окончательное решение принимает назначенный врач-эксперт или уполномоченная комиссия медицинской организации.

## 2. Объект проверки

Проверка выполняется отдельно по каждому назначению или решению: препарат, доза, кратность, путь введения, длительность, метод, исследование.

## 3. Два независимых параметра

### 3.1. Отношение к протоколу

| Значение | Условие |
|---|---|
| Соответствует | Протокол регулирует вопрос, назначение в пределах указанного (включая допустимый диапазон) |
| Отличается | Протокол регулирует вопрос, назначение выходит за его пределы |
| Не урегулировано | В проверенном наборе применимых протоколов прямая рекомендация не найдена |
| Невозможно проверить | Нет данных для сравнения (не указаны доза, масса, время и т. п.) либо применимый протокол отсутствует в реестре |

Формулировка для «не урегулировано» всегда такая: «прямая рекомендация не найдена в проверенном наборе применимых протоколов». Формулировка «в протоколах РК рекомендации нет» запрещена.

### 3.2. Подтверждение показаний

| Значение | Условие |
|---|---|
| Подтверждены | В истории есть данные, соответствующие показанию (диагноз, посев, лабораторные данные, факторы риска, клиника) |
| Не подтверждены | Проверена полная история, подтверждающих данных нет |
| Недостаточно данных | Предоставлен только фрагмент истории или данные противоречивы |

Параметры независимы: назначение может одновременно «отличаться» от протокола и иметь «не подтверждённые» показания.

### 3.3. Допуски по дозам

Универсальный допуск (например, «до 10 %») не применяется. Сравниваются конкретные параметры: доза на кг, разовая и суточная доза, интервал, гестационный и постнатальный возраст, функция почек и печени, если она влияет на препарат. Назначение внутри диапазона, прямо установленного протоколом или инструкцией, отклонением не считается.

## 4. Пять блоков проверки

Каждый факт хранится с источником: дата, время, фрагмент истории, раздел документа.

1. **Назначение.** Что назначено; результат поиска по протоколам (раздел 6); значение параметра 3.1; в чём отличие.
2. **Показания.** Факты из истории и значение параметра 3.2. Программа ничего не домысливает.
3. **Научное обоснование.** Четыре отдельные проверки:
   - **наличие:** источник предъявлен (ссылка, DOI/PMID, PDF) или нет;
   - **достоверность:** источник найден и проверен (PubMed, журнал, DOI) человеком или инструментом; иначе «не проверен»;
   - **применимость к ребёнку:** совпадение популяции: гестационный возраст, масса, постнатальный возраст, диагноз; результат «совпадает / частично / не совпадает / не определено»;
   - **соответствие схемы:** препарат, доза, путь введения, длительность совпадают с исследованием «да / частично / нет / не определено».
   Ограничения исследования и год публикации записываются. Источники программа не выдумывает.
4. **Документация.** Запись врача с обоснованием, оценка пользы и рисков, мониторинг эффективности и безопасности, консилиум, согласие (если требуется). Для каждого пункта одно из трёх:
   - найдено;
   - не найдено в предоставленном фрагменте;
   - не найдено после проверки полной истории.
   Программа не считает историю полной, если это не указано при загрузке.
5. **Вывод.** Статус по разделу 5 и сигналы безопасности по разделу 7.

## 5. Статусы и их приоритет

Программа предлагает один статус. Если подходят несколько условий, выбирается первый по списку.

| № | Статус | Условие |
|---|---|---|
| 1 | Требуется срочная оценка эксперта | Есть хотя бы один сигнал безопасности (раздел 7) |
| 2 | Недостаточно данных | Отношение к протоколу «невозможно проверить», либо показания «недостаточно данных», либо ключевые документы «не найдены в предоставленном фрагменте» |
| 3 | Соответствует протоколу | Отношение «соответствует», показания подтверждены |
| 4 | Обоснованное отклонение | Отношение «отличается» или «не урегулировано», и выполнены все условия раздела 5.1 |
| 5 | Требуется оценка эксперта | Обоснование есть, но применимость или схема «частично / не определено», либо данные противоречивы |
| 6 | Отклонение документировано не полностью | Остальные случаи; программа перечисляет, чего именно нет |

Статус «Потенциальный дефект» программа автоматически не ставит. Его может установить только эксперт.

### 5.1. Условия «обоснованного отклонения»

Все одновременно:
- показания подтверждены;
- источник предъявлен и проверен;
- применимость к ребёнку «совпадает», либо «частично» с записью врача о причине переноса данных;
- схема «совпадает», либо «частично» с записью врача о причине;
- запись врача с обоснованием найдена;
- консилиум проведён, если он обязателен (раздел 8).

Статус не означает, что назначение доказанно правильное и что комиссия его примет.

### 5.2. Ручное изменение

Эксперт может изменить любой статус, указав причину и источник решения. Исходный результат программы и все изменения сохраняются в журнале версий.

## 6. Поиск по протоколам

Для каждого назначения сохраняется:
- перечень просмотренных протоколов: номер, дата утверждения, редакция, дата действия;
- проверенные разделы;
- критерии применимости протокола к ребёнку (диагноз, возраст, масса);
- дата проведения поиска;
- полнота реестра: сколько протоколов в реестре, какие применимые протоколы в него не внесены.

Протокол выбирается по редакции, действовавшей на дату оказания помощи. Если это определить нельзя, отношение к протоколу «невозможно проверить».

## 7. Сигналы безопасности

Сигнал — это предупреждение о риске, а не заключение о дефекте. Виды:
- возможное противопоказание (по протоколу или инструкции);
- возможное превышение дозы (разовой, суточной, на кг);
- возможное несоответствие пути введения;
- возможное несоответствие интервала с учётом возраста и функции органов.

Каждый сигнал содержит источник требования (цитата) и факт из истории. Любой сигнал переводит статус в «Требуется срочная оценка эксперта».

## 8. Консилиум

Консилиум не обязателен автоматически при отклонении «не урегулировано».
- Обязателен, если это требование задано в настройках (локальный или нормативный документ, указанный экспертом).
- В остальных случаях программа рекомендует консилиум при высоком риске: применение вне инструкции, существенное отклонение от стандартной тактики, спорная ситуация, сигнал безопасности.

## 10. Требования к работе с данными

- До проверки правовых оснований обработки, требований к хранению и информационной безопасности в РК используются только синтетические или обезличенные истории.
- Псевдонимизация (замена ФИО, ИИН, номера истории) не равна полной анонимизации: по датам, редким диагнозам и сочетанию данных ребёнка можно узнать.
- Отметки согласия в программе недостаточно для работы с реальными данными.
- Исходная история не изменяется: модуль только читает.
- ИИ используется только для извлечения фактов и сопоставления. Статус определяется детерминированными правилами разделов 3–8. Любой источник проверяется человеком или инструментом проверки.

## 11. Пример

Назначен лечебный курс противогрибковой терапии ребёнку без порока развития диафрагмы.

В проверенных применимых разделах протоколов №4 (РДС), №185 (сепсис) и №231 (пороки развития диафрагмы) не обнаружена универсальная схема лечебной противогрибковой терапии для данной клинической ситуации. В №4 есть профилактика флуконазолом (масса <1000 г или ГВ ≤27 недель), в №185 — профилактика нистатином; №231 упоминает противогрибковую терапию по результатам посевов, но применим только к своей группе. Отношение к протоколу: «не урегулировано».

Назначение требует оценки клинических показаний, микробиологических данных, факторов риска, научного обоснования и документированного решения врача. Само отсутствие прямой рекомендации не является основанием для квалификации назначения как дефекта.

Это пример логики, а не подтверждение правильности конкретного назначения.

## 12. Критерии приёмки

1. Параметры 3.1 и 3.2 проверяются независимо; есть тест, где назначение одновременно «отличается» и показания «не подтверждены».
2. «Не урегулировано» не ставится без сохранённого перечня просмотренных протоколов и полноты реестра.
3. «Недостаточно данных» и «не найдено во фрагменте» не превращаются в «не документировано» или в дефект.
4. «Потенциальный дефект» программа автоматически не ставит.
5. Сигнал безопасности всегда даёт статус 1 и содержит цитату требования и факт.
6. Источники: только введённые врачом; непроверенный источник не даёт статуса «Обоснованное отклонение».
7. Назначение внутри диапазона протокола не считается отклонением.
8. Ручное изменение статуса сохраняет исходный результат.
9. Исходный текст истории не меняется.
10. Не менее 15 синтетических случаев:
    - по 2 на каждый из 6 автоматических статусов (12);
    - противогрибковая терапия с полным обоснованием и без него (2, могут входить в предыдущие);
    - сочетание «отличается» + «показания не подтверждены»;
    - источник о взрослых, применённый к недоношенному 700 г;
    - доза в пределах диапазона протокола (не отклонение);
    - предоставлен только фрагмент истории;
    - противоречивые данные в истории.

## 13. Решения по открытым вопросам версии 0.1

| Вопрос | Решение |
|---|---|
| Отдельные статусы для A/B/C | Нет. Единый набор статусов; отношение к протоколу и подтверждение показаний — отдельные параметры |
| Несущественные отклонения | Без универсального допуска; внутри диапазона протокола или инструкции — не отклонение (раздел 3.3) |
| Консилиум для «не урегулировано» | Не автоматически; по настройке или как рекомендация по риску (раздел 8) |
| Список протоколов ОРИТН | Отдельный версионируемый реестр с датами действия и актуальностью |
| Кто подтверждает «проверено» | Назначенный врач-эксперт или уполномоченная комиссия медицинской организации |

## 14. Открытые вопросы

1. Какие протоколы из 29 действуют на сегодня и какие редакции заменены (часть датирована 2014–2017)?
2. Есть ли в центре локальное требование о консилиуме при назначении вне протокола или вне инструкции?
3. Какой инструмент проверки источников допустим: PubMed по PMID/DOI автоматически или только ручная проверка экспертом?
4. Где брать инструкции к препаратам (для сигналов безопасности): Госреестр РК или иной источник?
